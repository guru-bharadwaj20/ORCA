# Releasing the ORCA VS Code extension

The extension is a thin front end that loads the `orca-agent-cli` engine at runtime, and
depends on the core by **published version range** (`"orca-agent-cli": "^0.2.0"`). Inside the
repo, npm workspaces still satisfy that range with the local symlink, so day-to-day
development is unaffected.

Do **not** change it to `"file:.."`. That works in the repo and breaks packaging, which is
an easy trap: `scripts/package-vsix.mjs` copies the extension into a temp directory and runs
`npm install` there, so `..` re-resolves against `/tmp` and npm links `node_modules/orca-agent-cli`
to a directory that is not the core. `vsce` then fails with `not a file`. That regression
reached CI once — the symptom appears in the packaging step, nowhere near the edit.

So a _distributable_ build has one hard prerequisite: **`orca-agent-cli` must be published to
npm first** (Stage 0), because the staged install pulls the core from the registry.

## Release checklist

1. **Publish `orca-agent-cli`** (from the repo root):

   ```bash
   npm publish            # publishes the root orca-agent-cli package
   git tag v<version> && git push --tags
   ```

2. **Point the extension at the published core.** In `vscode-extension/package.json`,
   set the dependency to `"orca-agent-cli": "^<published version>"`, then run
   `npm install` to update the lockfile. Note: inside the repo, npm workspaces will
   still satisfy this with the local symlink — which is why packaging goes through
   `scripts/package-vsix.mjs` (staged outside the workspace so the real registry
   package is installed and packed).

3. **Bump the extension version** (`vscode-extension/package.json` `version`, currently
   `0.0.0`) and update `CHANGELOG.md`.

4. **Replace the placeholder assets** — `media/icon.png` (generated by
   `scripts/make-icon.mjs`) with real artwork, and add a demo GIF of the approval webview
   to `README.md`.

5. **Package & verify:**

   ```bash
   npm run package -w orca-vscode      # runs scripts/package-vsix.mjs → orca-vscode.vsix
   ```

   Install the `.vsix` locally (Extensions view → “Install from VSIX…”) and run
   **ORCA: Preview Repo (Dry Run)** to confirm it loads.

6. **Publish to the Marketplace** (requires a registered `orca` publisher + a PAT):
   ```bash
   npx vsce login orca
   npx vsce publish -w orca-vscode
   ```

## Notes

- The `esbuild --external:orca-agent-cli*` flags stay as-is — `orca-agent-cli` is always loaded from
  node_modules at runtime (never bundled), because its ESM template loader relies on
  `import.meta.url`, which is empty in a CJS bundle.
- `mermaid.min.js` is copied into `media/` at build time and shipped in the `.vsix`
  (offline, CSP-safe). It is large (~3.4 MB) but compresses well (~950 KB packed).
